# Prove it

Check the disputed assertions against evidence rather than repeating them.

## Extract claims

Identify each checkable assertion in the targeted passage: numbers, dates,
versions, names, decisions, file contents, configuration, and behavior.
Start with the claims whose failure would most affect the answer. Keep
opinions and explicitly labeled speculation distinct.

## Verify

Choose sources according to the claim:

- **Project state or past decisions:** read the relevant project records
  and instructions. Check whether a conflicting record is stale.
- **Code, configuration, or tool behavior:** inspect the actual artifact
  or run an available harmless check.
- **External or changing facts:** use current authoritative sources,
  preferably official documentation or primary evidence.

A remembered fact is a lead, not verification. Do not infer confirmation
from a lack of contradiction. If a source or check is unavailable, state
what is missing.

## Report

Give a short verdict for each claim, with its source:

- **Confirmed:** the evidence supports it.
- **Wrong:** state the correct fact and what was mistaken.
- **Unverified:** withdraw it as an assertion until evidence supports it.

If any claim is wrong or unverified, provide the corrected answer in a
compact paragraph. State whether the correction changes a recommendation
or action. Keep the claims and explanations in plain English.
